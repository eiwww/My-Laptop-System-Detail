03 What are "dotfiles," actually?

The word you keep seeing everywhere in this rice — here's what it means.

Dotfiles are config files whose names start with a dot (.bashrc, .gitconfig) — on Linux, a leading dot means "hidden file." Almost every app on Linux reads its settings from a plain text config file instead of a GUI settings panel buried in a database. "My dotfiles" = the collection of these text files that define how your terminal looks, how your window manager behaves, your keybinds, your color scheme — your entire setup, as version-controllable text.

That's why people share dotfiles as GitHub repos, and why you have a folder called caelestia — it's someone else's published dotfiles repo that you installed and are now customizing on top of. Yours live in two places:

~/.config/hypr → symlink → ~/.local/share/caelestia/hypr # the base rice (caelestia-dots) ~/.config/caelestia/hypr-vars.conf # YOUR overrides (editor, browser, keybinds) ~/.config/caelestia/hypr-user.conf # YOUR extra binds & settings, loaded last ~/.config/hypr-profiles/jakoolit/ # a second rice (JaKooLit's) you borrowed pieces from

04 Your rice, unpacked

"Ricing" = customizing a Linux desktop's look and feel. Yours is a base theme with your own tweaks layered on top, so upstream updates don't wipe out your changes.

🧱 Base: caelestia-dots

A full Hyprland + Quickshell config framework. Provides the bar, sidebar, launcher, lock screen, notifications, and a dynamic Material You color engine that derives a whole palette from your wallpaper.

🎛️ Borrowed: JaKooLit profile

A popular, separate Hyprland dotfiles project. You pulled its keybind style, fastfetch config, and kitty terminal config in via ~/.config/hypr-profiles/jakoolit.

✍️ Your overrides

hypr-user.conf and hypr-vars.conf in ~/.config/caelestia/ — this is where your personal choices live (default editor, terminal, browser, extra keybinds) without editing caelestia's own files directly.

Why layer it this way? Editing caelestia's source files directly would mean losing your changes every time you git pull an update to the base rice. Keeping your personal config in separate override files means the base theme can update cleanly while your customizations persist.

05 Tool glossary

Every unfamiliar name in your config folders, explained in one line each.

Hyprland
The tiling Wayland compositor — your actual window manager. Handles window placement, animations, workspaces, and keybinds.
Quickshell (qs)
A toolkit for building desktop shells (bars, widgets, launchers) in QML. caelestia's entire visible UI — top bar, sidebar, on-screen-display — is built with it.
Kvantum
A theme engine for Qt apps (Dolphin, KDE apps, some Discord clients). Yours is set to catppuccin-mocha-blue.
Breeze
KDE's default GTK icon/cursor/widget theme — still active for your GTK apps (file pickers, GTK-based programs) even though you're not running a KDE session.
fuzzel
A fast, minimal Wayland application launcher (what pops up to search/run apps).
cava
A terminal audio visualizer — those animated bars that react to music.
OpenRGB
Cross-vendor RGB lighting control, for your ROG laptop's keyboard/chassis lighting.
nwg-look / nwg-displays
GUI tools for setting GTK themes and arranging monitors on wlroots-based compositors like Hyprland.
spicetify
Lets you re-theme and add plugins to the official Spotify client.
swappy
A quick screenshot annotation tool (crop, draw, blur before saving/copying).
app2unit
Launches apps as their own systemd transient units instead of plain child processes — keeps resource accounting and cleanup tidier.
AUR (Arch User Repository)
A community package repository beyond Arch's official ones. yay and paru (both installed on your system) are "AUR helpers" that build and install from it automatically.
pacman
Arch's native package manager — installs, updates, and removes official packages.
